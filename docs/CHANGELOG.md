## 接收「OpenPetCare 产品变更单」

变更单至少应说明：确认日期、已确认的具体变化、影响范围、验收标准。建议同时提供变更编号、背景及与旧决定的关系。收到后先比对 `PRODUCT_SPEC.md`、`DECISIONS.md`、`ARCHITECTURE.md`、`ROADMAP.md` 和本文件，再按需更新相关文档与测试；无法确认的内容先列为待澄清，不擅自实施为正式方向。

每条正式记录包含：**日期、来源/确认方式、影响范围、变更内容、与旧版差异或冲突、验收标准、代码/测试影响、实施状态**。文档更新与代码完成是两个独立状态；Git 提交保存实际改动。更正旧决定时追加“取代哪条记录”，不删除原文。

## 2026-11-01｜UX-001：低负担建档、主动食品检索与兽医门槛纠偏

- **来源/确认方式**：项目负责人在豆包工作实际安装体验后提交反馈，并明确批准中文优先的改动设计。
- **影响范围**：`SKILL.md`、每日照护缺口输出、BCS 建档引导、狗粮资料检索、安装包、README、正式产品与测试文档。
- **变更内容**：缺 BCS 时以中文解释 1–9 分体况评分，并通过“偏瘦 / 理想 / 偏胖 / 不确定”再细分的两步流程帮助主人自评；主人给出品牌、完整系列、口味或配方后，具备联网能力的宿主先查购买地区的制造商官方资料，确实无法唯一匹配时才索取包装上的最小字段；健康成年犬满足既定条件时直接提供非处方起始估算，兽医目标只在用户已有时优先。
- **与旧版差异或冲突**：原产品需求已允许健康成年犬使用通用起始估算，但实现中的部分失败提示把兽医目标表现成默认替代项，宿主进一步误写成“唯一道路”；原 Skill 也只列出 BCS 和热量字段，没有告诉用户如何回答或要求宿主先检索。本条纠正实现偏差，不取消资料不足时拒绝编造数字、危险信号分流或既有兽医医嘱优先级。
- **验收标准**：面向用户的引导以中文为主；缺 BCS 时提供可选择的自评路径并允许“不确定”；缺食品热量时优先返回精确官方检索动作；合格健康成年犬无兽医目标仍输出起始 kcal 与克数；危险信号、已知疾病、治疗性饮食及明确限制仍阻止不适用的通用计算。
- **代码/测试影响**：更新 Skill 与安装包参考资料；照护结果增加机器可读的补资料动作并移除将兽医目标作为普通缺失项的提示；新增对应回归测试和隔离安装测试。真实品牌网页检索依赖宿主联网能力，须另做人工验收，不能由本地单元测试冒充通过。
- **实施状态**：已实施；18 项自动测试、Skill 规范校验和隔离安装冒烟测试通过。精确产品的真实联网检索，以及豆包工作中的重新安装、命令执行和跨会话持久化仍待人工复测。
