# OpenPetCare v0.1 架构

## 运行边界

OpenPetCare 是一套 Agent Skill 加本地 Python 程序，不提供独立聊天模型、账号、云数据库或常驻服务。宿主 AI 将自然语言整理为经用户确认的结构化输入，并调用 `scripts/opc.py`；程序负责验证、计算和持久化。宿主必须真的具备本地执行与持久文件系统，才可以承诺跨会话读取。

```
用户自然语言
  → 宿主 AI：理解意图、追问、解释证据与风险
  → SKILL.md：照护及安全工作流
  → scripts/opc.py：结构化命令入口
  → Python 核心：档案校验 / 确定性计算 / 提案版本 / 数据读写
  → 系统持久应用数据目录
```

## 分层职责

| 层 | 职责 | 不负责 |
| --- | --- | --- |
| Skill | 把用户意图映射到命令，使用中文引导 BCS；在宿主具备联网工具时检索精确食品官方资料；要求展示依据、缺口和变更差异，设置医疗边界 | 独立储存资料、暗中后台调度、假装完成未执行的网页检索 |
| CLI 与数据校验 | 稳定命令、结构化输入输出、拒绝非法或矛盾数据 | 自然语言理解 |
| 科学照护核心 | 可重复的日期、生命阶段、能量和份量计算；在证据不足时不给数字 | 诊断、药量、把经验值伪称标准 |
| 持久数据层 | 版本化档案、有效计划、待确认提案、历史、备份与导入导出 | 远程同步 |

程序输出应区分原始输入、确定性推导、一般建议和无法确定的项目。医疗警示优先于日常照护计算。有效计划只有明确确认提案或按用户指定版本恢复时才能改变。

食品网页检索属于宿主能力，不加入本地核心的网络依赖。宿主只把与品牌、完整产品线、口味或配方、形态、生命阶段和地区精确匹配的制造商官方资料整理为结构化输入；本地程序继续负责字段校验、热量换算后的照护计算和持久化。找不到唯一官方匹配时，宿主只向用户索取包装上的最小缺口，不使用零售商摘要或相似产品代替。

## 数据与隐私

默认写入操作系统持久应用数据目录，绝不写入 Skill 安装目录；程序的 `--data-dir` 仅用于测试与显式迁移场景。个人档案、事件、计划、提案和备份均不属于仓库示例数据。磁盘写入应采用临时文件、校验和原子替换；备份和导入要验证版本及完整性。数据格式与迁移规则见 [DATA_SCHEMA.md](DATA_SCHEMA.md)。

宿主可能把与提问有关的档案内容传给所用 AI 服务。OpenPetCare 不控制该服务的资料处理。离线本地程序仍可直接运行，但自然语言交互依赖宿主 AI。

## 宿主安装路径

根目录 `SKILL.md` 是可移植包的入口，`agents/openai.yaml` 提供 Codex 展示名称、简介和默认调用提示，`scripts/opc.py` 与核心 Python 模块随包一起保留。仅把文件放在仓库根目录并不能保证被宿主发现：Codex 本地扫描仓库 `.agents/skills/<name>/SKILL.md` 或用户 `~/.agents/skills/<name>/SKILL.md`；Claude Code 本地扫描项目 `.claude/skills/<name>/SKILL.md` 或用户 `~/.claude/skills/<name>/SKILL.md`。两者都支持技能目录的符号链接；当前安装脚本复制最小 Skill 包，真实数据目录仍与安装包分离。

Codex 的技能可被相关任务自动选中，也可显式用 `$openpetcare` 调用；Claude Code 可用 `/openpetcare`。命令是否可在具体宿主执行及跨会话留存，必须以实际运行验证为准。云端临时环境的技能发现和持久化不作为 v0.1 承诺。

2026-10-30 在本机 Codex CLI 0.165.0-alpha.1.2 做了隔离发现测试：把仓库根目录链接到 `/tmp` 测试仓库的 `.agents/skills/openpetcare`，用独立 `CODEX_HOME` 运行 `codex debug prompt-input`，模型可见技能列表包含 `openpetcare` 及正确的 `SKILL.md` 路径。此测试只证明本地发现，不证明模型已实际调用命令或客户端重启后的资料留存。Claude Code 2.1.42 仅确认本机已安装，尚未进行真实 AI 会话验收。

## 后续扩展界线

可在不改变本地数据所有权的前提下，为未来 MCP 或可视界面增加适配器；v0.1 不为这些可能性创建服务、账号或抽象层。资料导出、导入、版本号为未来迁移提供基础。
