# OpenPetCare Skill v0.1 产品需求（冻结基线）

本文件以 2026-10-30 的实施交接指令为准。工作区开始时为空，没有可整合的原始 ChatGPT 对话或其他需求材料；如后续取得较早资料，冲突处以本次明确决定为准，并记录在 `DECISIONS.md`。

## 目标与范围

OpenPetCare 是免费的开源 Agent Skill，让用户已有的兼容 AI 客户端获得基于真实犬只档案的持续照护能力。首版只支持狗，并优先验证本地执行的 Codex；Claude Code 的安装及行为须单独验证。自然语言理解由宿主 AI 完成，本项目提供可靠的本地命令、数据和规则，不提供通用聊天模型、云账号、云数据库、实时同步、OCR、包装识别、PWA、小程序或图形界面。

首版成功路径：安装 Skill → 用自然语言建立档案 → 生成当日照护建议 → 换粮时生成待确认提案 → 主人确认后更新有效方案 → 关闭并重开客户端后仍能读取档案、当前计划及历史。

## 犬只档案

档案覆盖身份与年龄（名称、犬种/混种、预计成年体型、生日或带参考日期的估计年龄），身体状况（体重、BCS、性别、绝育状态），饮食（类型、主粮、标签适用生命阶段、完整均衡声明、包装标注热量及单位、餐次、零食、当前喂食量），活动与居住情况，过敏、病史、兽医禁忌，已确认的免疫与驱虫事项，以及主人可用时间和预算。

未知资料明确保存为未填写；不得假造默认档案或犬种。昵称允许中文、英文和 emoji：中文等宽字符计 2 单位，ASCII 计 1 单位，总上限 24 单位；组合 emoji 按一个可见字符处理。犬种尽可能使用可靠标准参考名及中英文别名；无法核实就保存主人原话，并标为待核验。

## 每日照护

按日期重新判断犬龄、生命阶段和已确认日程。可用资料与来源允许时，给出主粮每日总量、餐次与每餐数量、建议时间、零食 kcal 额度、适用条件明确的饮水参考、活动和嗅闻互动建议、阶段性护理与重要日程。只有距离有可靠估算依据时才换算 400 米跑道圈数。

每项建议应说明来源类型（原始资料事实、确定性推算、一般经验或无法确定）、适用条件、不确定性和必要安全提示。缺少包装热量、生命阶段、体重或健康限制等关键数据时，明确指出缺口，不给貌似精确的克数。对资料完整、BCS 4–5/9、明确无相关病史/兽医限制/危险信号、食物标签适用且明确为完整均衡的健康成年犬，已核验的通用能量公式可作为**非处方起始估算**；程序暂以 24–84 月龄作保守适用边界，此范围不是权威生命阶段定义。兽医确认的个体目标优先，并在其他年龄阶段仍需核对必要资料与安全条件。既有有效计划在条件未变时保持稳定。产品主动给方案，不设置打卡、完成率、监督或虚构后台推送。

## 反馈与变更

宿主 AI 读取当前档案，识别主人反馈中的变化，索取关键缺口，调用确定性规则，展示变更原因及前后差异。新方案先成为待确认提案；主人明确确认后才写入有效计划，并保留原版本。应能从历史有效版本恢复，恢复也留下历史记录；若年龄、体况、医疗、预防或兽医热量目标已有变化，须基于当前资料重新提案，不能直接恢复旧档案覆盖安全信息。兽医限制优先于一般照护建议。

## 健康安全

可回答可靠资料范围内的犬类健康、营养、预防护理和观察事项。不得独立确诊、虚构药量或治疗方案、覆盖兽医医嘱。潜在急症先提醒及时联系兽医或急诊，再收集有助于就医的信息；不能因数据不完整给出有风险的活动或饮食数值。详见 `SAFETY_POLICY.md`。

## 数据与隐私

档案、计划、事件历史写入用户系统的持久化应用数据目录，与 Skill 安装位置分离。支持版本化数据、安全写入、损坏检测、备份、导入导出和迁移路径。示例、测试及 Git 仓库不得包含真实用户资料。使用云端 AI 宿主时，完成任务所需资料仍可能传给其服务商，不能承诺数据绝不离开设备。

## 发布边界

开源代码免费；第三方 AI 客户端或模型服务的费用由对应服务商决定。Skill 安装本身不提供后台定时能力；只有宿主调度和日历授权被实际验证后，才能宣称自动提醒。
