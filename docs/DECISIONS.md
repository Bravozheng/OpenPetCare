## 实施取舍

v0.1 使用 Python 标准库实现本地命令，避免安装时依赖付费 API 或外部数据库。每犬一份带校验和的 JSON 文件；写入采用临时文件与原子替换，快照和事件保留计划历史。数据格式从 `schema_version: 1` 开始；首版没有旧版存量可迁移。未知未来版本应拒绝静默读取或降级，未来新增格式时再写显式迁移及回归测试。

科学计算采用已核验的 RER 和健康成年犬 MER 系数作为严格前提下的**非处方起点**：程序只在 24–84 月龄、BCS 4–5/9、明确无相关病史/兽医限制/危险信号、主粮标签适用于成年期且有完整均衡声明等条件满足时使用。24–84 月龄是首版保守的程序边界，不是权威生命阶段定义。若有兽医确认的每日热量目标则优先，其他年龄仍要有必需资料并通过安全检查。包装热量密度和零食热量缺失时不换算主粮克数。历史恢复不得覆盖之后变化的年龄、体重、BCS、医疗、预防或兽医热量目标。散步时长以主人报告的现实基线为讨论起点，不把通用里程或分钟数说成权威标准。详见 `SCIENCE_SOURCES.md` 和 `SAFETY_POLICY.md`。

具体数据格式、命令和计算边界以 `DATA_SCHEMA.md`、`ARCHITECTURE.md` 和可执行代码为准。任何后续取舍若改变上表的产品方向，应先由项目负责人确认并在此记录。未核验的科学数字不得因为实现方便被写成默认规则。

## 低负担建档与非处方起始估算决策（2026-11-01）

- **影响范围**：建档对话、BCS 收集、狗粮资料补全、每日饮食结果和宿主提示。
- **已确认决定**：面向用户的交互以中文为主。缺 BCS 时必须解释并提供可选择的两步自评，允许“不确定”；已给出狗粮身份信息时，具备联网能力的宿主先查精确产品的制造商官方资料，无法唯一匹配后才向用户索取包装上的最小字段。资料完整且通过安全条件的健康成年犬可直接获得 Merck 公式的非处方起始估算；兽医目标只在用户已有时优先，不是普通计算的门槛。
- **验收标准**：缺 BCS 的输出包含中文自评动作；缺精确热量的输出优先指向官方资料检索；无兽医目标的合格健康成年犬仍返回 kcal 和克数；危险信号、已知疾病、治疗性饮食和兽医限制仍阻止不适用的通用估算。
- **与先前决定的关系**：纠正了实现提示中把兽医目标表现成默认或唯一出口的偏差，不改变“资料不足时不编造数字”和“医疗风险保守分流”的原决定，也不扩展当前 24–84 月龄、BCS 4–5/9 的程序边界。
